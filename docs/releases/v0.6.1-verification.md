before publication.

published, non-prerelease release. The annotated tag resolves to
`3235808fe9efd390d8b3c87e369a8eea675473c9`. The public latest-release endpoint
returned this version and the reviewed release notes.

Both [main CI](https://github.com/ersinkoc/AI-Video-Factory/actions/runs/44076022584)
and [tag CI](https://github.com/ersinkoc/AI-Video-Factory/actions/runs/44076139153)

- Eight explicit PostgreSQL/RustFS integration tests and 12 real-Git release
  ownership cases. The normal suite's two opt-in integration skips remain separate.
- Frozen installation, production dependency audit, typecheck and Studio build.
- Real offline MP4 render, technical audits and main/Short decision isolation.

The three downloaded main-CI ZIP digests matched GitHub's artifact metadata.
Six retained render-manifest entries matched their SHA-256 hashes. Three render
caches and one sources sidecar were not uploaded by the workflow and were not
independently verified from those artifacts. The downloaded source ZIP matched
all 575 tracked files, installed with the frozen lockfile and reported
`AI Video Factory v0.6.1`. Its environment doctor passed with an explicit existing
Chrome executable; without a browser cache/configuration the fresh installation
correctly reported that prerequisite missing. Optional Manim warned in this probe.

## Running Studio

The existing listener on `127.0.0.1:3100` was already a newer process when the
post-release checks began. Its start followed the local production build, and
Next.js 16.4.5 was installed before both. No process was stopped, restarted or
replaced during this continuation.

The running UI displayed v0.6.1 and the Shots review workspace. Five read-only
HTTP requests passed against one completed production episode:

- Library summaries and lightweight status/revision response.
- Shots panel with `sourceRevision`, canonical main `outputVersions` and 54 shots.
- Quality evidence response.
- Export-bound main video request: HTTP 206 with the requested 1,024-byte range.

The lightweight status body was 1,451 bytes and the selected Shots payload was
336,125 bytes in this sample. These are single observations, not latency or
payload-distribution benchmarks. Episode count changed between observations of the
shared library; no frozen production-library denominator is claimed.

The inspected episode state, quality-decision presence/content and generation
ledger bytes matched the fingerprints captured before the read-only probes. No
approval, decision, regeneration, audit rerun or deletion action was submitted.

## Browser observations and remaining acceptance

The in-app browser still returned an unavailable-host error. The installed Windows
Computer Use connection worked, so an owned Chrome test window was used and then
closed; the original Chrome window was preserved.

Observed in desktop Chrome:

- Library filters, queue labels, cost disclosures and episode navigation rendered.
- Completed episode overview, Shots workspace, thumbnails and source selector
  rendered. Code preview and recorded main output had separate labels.
- Recorded main video displayed its export identity and visibly advanced through
  frames. The Costs tab opened; a later accessibility snapshot no longer reported
  the tab as playing audio. Exact pause/current-time state was not instrumented.

Chrome's responsive toolbar confirmed **390 × 844**. The episode header, costs
and next-action area remained readable in the observed viewport. Navigation
wrapped over several rows and occupied a substantial part of that viewport;
the episode tabs used horizontal scrolling. A compact mobile navigation pilot
is a usability follow-up, not a measured task-time improvement.

The console exposed warnings originating at `contentscript.js`, including
MaxListeners and orphaned-stream warnings. An extension-free console/reload check
was not performed. These messages do not establish an application memory leak or
a clean application console.

Native media accessibility controls were inconsistent during automation, and the
helper detected intervening user input. Full keyboard focus/arrow navigation,
modal focus restoration, screen-reader acceptance, mobile playback/issue workflows,
Short playback, clean-profile console checks and GPU profiling remain pending.
This is a bounded live smoke, not completion of all D acceptance tasks or human
editor-task timing. Human comparison sample size remains zero.
